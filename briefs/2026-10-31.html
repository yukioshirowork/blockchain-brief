Blockchain Brief, 31 Oct 2026

The Binance theft turns out to have run through EIP-7702 delegation, Bitcoin Core ships its first fast-track security fixes, and Lightning gets another round of patches.

Follow-up · Binance · 30–31 Oct

How the Binance drain worked

On-chain analysis shows that one of Binance's Ethereum hot wallets was placed under an EIP-7702 delegation pointing at attacker code with a sweep function. At about 20:24 UTC on 29 October it moved roughly 167,000 ETH and over 1.6 billion USDT in one go (Threat Landscape). Binance co-CEO Richard Teng said the delegation “did not pass through our normal approval controls,” that investigators found further breach points beyond the engineer's laptop, and that the attacker used a self-destruct mechanism to wipe tools (Cointelegraph).

EIP-7702 did not cause the hack, since the attacker still needed Binance's signing access, but it let one signature hand over a whole wallet. The attacker also borrowed about $44.6M of WETH from Aave against stolen USDT before Aave froze markets (Blockchain Reporter).

UnverifiedSources disagree on whether the authorizations were phished or signed with a stolen key.

Follow-up · Bitcoin Core 32.1 · 28–30 Oct

Bitcoin Core's first fast-track fixes

Bitcoin Core's new policy of publishing fixes for easily rediscovered bugs immediately has now been used. Bitcoin Core 32.1, 31.2, 30.4 and 29.5 shipped with fixes for memory exhaustion via TCP urgent data, a send-buffer timeout issue, and a 4 GiB overflow in undo files, with advisories published at the same time (Bitcoin Optech #429). Version 32.0 was tagged but never released, so 32.1 is the first release of the new major version, with PSBT v2 by default and mempool-based fee estimation.

Follow-up · Lightning · Optech #429

More Lightning patches

Core Lightning disclosed a crash bug in versions 25.02 to 26.04: a channel announcement naming the same node at both ends crashed the node, and because the message was stored, it crashed again on every restart. It is fixed in 26.04.1. Eclair shipped security release 0.14.6 for splicing and on-the-fly funding, and LND's v0.21.5 and v0.20.6 are now final (Bitcoin Optech #429).

What to do this week

  • Treat an EIP-7702 authorization like a transfer of the whole account. Route it through the same approvals and alerts as large withdrawals.
  • Monitor custody addresses for delegation changes and alert on any code being set on an EOA.
  • Lending protocols should prepare for stolen collateral and have a fast freeze process, as Aave did.
  • Bitcoin services should test PSBT v2 handling before moving to Core 32.1.

Binance · Plain summary

One signature handed over a whole wallet

The Binance thieves used a newer Ethereum feature that lets a wallet hand control to a piece of code. Once that permission was set on one of Binance's wallets, the attacker could empty it in a single step. The same feature is behind many phishing losses for ordinary users. Binance has set aside more than $6.34 billion to cover customers and says about $3 billion is frozen. Withdrawals were set to restart in phases around 1 November.

UnverifiedThe restart time has shifted several times. No funds have been reported recovered.

Bitcoin · Plain summary

Bitcoin and Lightning software updates

Bitcoin's main software got security fixes that were published right away, under a new policy. Several Lightning wallets' underlying software was patched too. If you run your own node, update. If you use an app, keep it updated.

As a user

  • If you have funds on Binance, wait for withdrawals to reopen in the app and check the proof of reserves when it is published.
  • Check whether your own Ethereum address has an active EIP-7702 delegation, and revoke any you did not set up.
  • Bitcoin node runners should upgrade to 32.1 or the matching point release now.
  • Lightning node operators should update CLN, Eclair and LND.

Coming up: Binance's withdrawal restart, proof of reserves and post-mortem, and where the remaining stolen funds go.

続報 · Binance · 10月30〜31日

Binance の流出の仕組み

オンチェーン分析によると、Binance のイーサリアムのホットウォレットの1つが、スイープ関数を持つ攻撃者のコードを指す EIP-7702 の委任下に置かれました。10月29日 20:24 UTC ごろ、約16万7,000 ETH と16億 USDT 超が一度に移されました（Threat Landscape）。Binance の共同 CEO Richard Teng は、委任が「通常の承認管理を通っていなかった」こと、調査でエンジニアのノート PC 以外にも侵入箇所が見つかったこと、攻撃者が自己破壊の仕組みでツールを消したことを明らかにしました（Cointelegraph）。

攻撃者は Binance の署名権限を必要としたため、EIP-7702 がハッキングの原因ではありませんが、1つの署名でウォレット全体を渡せてしまいました。攻撃者は Aave が市場を凍結する前に、盗んだ USDT を担保に約4,460万ドル分の WETH も借りています（Blockchain Reporter）。

未確認承認がフィッシングによるものか、盗まれた鍵で署名されたものかで情報が分かれています。

続報 · Bitcoin Core 32.1 · 10月28〜30日

Bitcoin Core 初の即時公開修正

再発見されやすいバグの修正をすぐに公開するという Bitcoin Core の新方針が、初めて使われました。Bitcoin Core 32.1、31.2、30.4、29.5 は、TCP 緊急データによるメモリ枯渇、送信バッファのタイムアウト問題、undo ファイルの 4 GiB オーバーフローの修正を含み、勧告も同時に公開されました（Bitcoin Optech #429）。32.0 はタグ付けされたもののリリースされなかったため、32.1 が新しいメジャーバージョンの最初のリリースで、PSBT v2 が既定になり、mempool に基づく手数料見積もりが入りました。

続報 · Lightning · Optech #429

Lightning の追加パッチ

Core Lightning は、バージョン 25.02〜26.04 のクラッシュバグを公表しました。両端に同じノードを指定したチャネル告知を受け取るとノードがクラッシュし、そのメッセージが保存されるため再起動のたびにクラッシュしました。26.04.1 で修正されています。Eclair はスプライシングとオンザフライ資金調達に関するセキュリティリリース 0.14.6 を出し、LND の v0.21.5 と v0.20.6 も正式版になりました（Bitcoin Optech #429）。

今週やること

  • EIP-7702 の承認はアカウント全体の譲渡として扱い、大口出金と同じ承認と通知を通す。
  • カストディのアドレスで委任の変更を監視し、EOA にコードが設定されたら通知する。
  • レンディングプロトコルは盗難資産の担保に備え、Aave のように素早く凍結できる手順を持つ。
  • ビットコインのサービスは、Core 32.1 に移る前に PSBT v2 の処理をテストする。

Binance · やさしい解説

1つの署名でウォレット全体が渡ってしまった

Binance の窃盗犯は、ウォレットの操作権限をプログラムに委ねられるイーサリアムの新しい機能を使いました。Binance のウォレットの1つにその権限が設定されると、攻撃者は一度で中身を空にできました。同じ機能は、一般の利用者のフィッシング被害の多くにも使われています。Binance は顧客補償のために63.4億ドル超を確保し、約30億ドルが凍結されているとしています。出金は11月1日ごろから段階的に再開される予定でした。

未確認再開時刻は何度も変わっています。資金の回収はまだ報告されていません。

Bitcoin · やさしい解説

ビットコインと Lightning のソフト更新

ビットコインの主要ソフトに、新しい方針のもとですぐ公開されたセキュリティ修正が入りました。複数の Lightning ウォレットの基盤ソフトも修正されています。自分でノードを動かしているなら更新を、アプリを使っているならアプリを最新に保ちましょう。

利用者として

  • Binance に資金があるなら、アプリで出金の再開を待ち、準備金証明が出たら確認する。
  • 自分のイーサリアムアドレスに有効な EIP-7702 の委任がないか確認し、心当たりのないものは取り消す。
  • ビットコインのノード運用者は今すぐ 32.1 か対応するポイントリリースにアップグレードする。
  • Lightning ノードの運用者は CLN、Eclair、LND を更新する。

今後の予定：Binance の出金再開、準備金証明と事後報告、残る盗難資金の行方。

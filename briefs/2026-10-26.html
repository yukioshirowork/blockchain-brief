Bitcoin · Lightning · patches 27 Sep–23 Oct

A month of Lightning security fixes

LDK 0.2.7 and 0.1.13 (1 October) fix a funds-theft bug: a malicious peer could acknowledge an update, disconnect, then claim on reconnect it never got it, tricking LDK into signing a conflicting commitment. Core Lightning v26.06.7 fixed a flaw where a revoked-state transaction could be mistaken for a cooperative close, skipping the penalty. On 2 October the CLN team warned that nodes on that version or older were being actively targeted (Shattered).

Eclair followed with 0.14.4 and 0.14.5, fixing trampoline routing, where a payer could steal from a forwarding node, and taproot splicing, where a peer could make Eclair sign an invalid splice. LND has release candidates out with further hardening (Bitcoin Optech #428).

UnverifiedNo losses have been confirmed. “$340M exposed” headlines refer to Lightning's total public channel capacity.

Chainlink · CCIP 2.0 · 2 Oct

CCIP 2.0 adds institution-run verification

Chainlink launched version 2.0 of CCIP, its cross-chain messaging and token protocol (The Paypers). An institution can now run its own Cross-Chain Verifier, which must approve a message before CCIP executes it, and add extra independent verifiers. Compliance screening can be applied to every transfer, and speed is configurable from near-instant to full finality. Bridges have been crypto's most costly attack surface, so letting the asset issuer hold a veto is a meaningful design change. OpenZeppelin has added CCIP to its developer tools (TokenPost).

UnverifiedThe $84B secured figure is Chainlink's own, and “launch partner” does not necessarily mean a live integration.

What to do this week

  • Pin and audit your Lightning library versions, and test reconnect and channel-reestablish edge cases.
  • For paid APIs, consider supporting both L402 (bitcoin) and x402 (stablecoins).
  • When integrating CCIP 2.0, decide who runs the verifier and what happens when it rejects or goes offline.
  • Follow Bitcoin Optech's weekly security-release section.

Lightning Labs · alpha · 25 Oct

Wavelength lets AI agents pay in bitcoin

Lightning Labs opened Wavelength to everyone. It lets software agents send and receive bitcoin over Lightning without a person approving each payment (TokenPost). It uses L402, which pairs the web's “Payment Required” error with a Lightning invoice, similar to Coinbase's x402 but settled in bitcoin instead of stablecoins. Developers don't need to run a node. Wallets stay self-custodial, start with a 300,000-sat limit (roughly $240), and pay a 0.25% service fee. It is still in alpha.

UnverifiedOnly one report so far, and no usage numbers.

Lightning · Plain summary

Update your Lightning wallet

The software behind most Lightning wallets, Bitcoin's fast-payment network, had several serious bugs fixed this month, and attackers were already probing for unpatched nodes. No losses have been confirmed, but updating your wallet app is the simple fix.

As a user

  • Update any Lightning wallet now, especially ones built on LDK such as Phoenix.
  • If you run your own Lightning node, upgrade to CLN v26.06.9, LDK 0.2.7, or Eclair 0.14.5 or newer.
  • Give AI agents their own small wallet with a spending limit, never access to your main funds.
  • Tokenized assets moving between chains may now carry issuer checks, so a transfer can be delayed or blocked by design.

Coming up: LND's final releases, a new Glamsterdam Hoodi date, and the first live CCIP 2.0 integrations.

Bitcoin · Lightning · 9月27日〜10月23日のパッチ

1か月にわたる Lightning のセキュリティ修正

LDK 0.2.7 と 0.1.13（10月1日）は資金窃取のバグを修正しました。悪意あるピアが更新を承認した後に切断し、再接続時に受け取っていないと主張することで、LDK に矛盾するコミットメントへ署名させられるというものです。Core Lightning v26.06.7 は、失効済み状態のトランザクションが協調クローズと誤認され、ペナルティが回避されうる欠陥を修正しました。CLN チームは10月2日、そのバージョン以前のノードが実際に狙われていると警告しました（Shattered）。

Eclair も 0.14.4 と 0.14.5 で、支払者が転送ノードから盗めるトランポリンルーティングの問題と、ピアが Eclair に不正なスプライスへ署名させられる taproot スプライシングの問題を修正しました。LND もさらなる強化を含むリリース候補を出しています（Bitcoin Optech #428）。

未確認損失は確認されていません。「3.4億ドルが危険に」という見出しは、Lightning の公開チャネル容量の総額を指しています。

Chainlink · CCIP 2.0 · 10月2日

CCIP 2.0 に機関が運用する検証を追加

Chainlink は、クロスチェーンのメッセージングとトークンのプロトコル CCIP のバージョン2.0を公開しました（The Paypers）。機関は独自の Cross-Chain Verifier を運用でき、CCIP が実行する前にメッセージを承認させたり、独立した検証者を追加したりできます。すべての送金にコンプライアンスのスクリーニングをかけられ、速度もほぼ即時から完全なファイナリティ待ちまで設定できます。ブリッジは暗号資産で最も被害の大きい攻撃対象だったため、資産の発行体に拒否権を持たせるのは意味のある設計変更です。OpenZeppelin も開発ツールに CCIP を追加しました（TokenPost）。

未確認840億ドルを保護という数字は Chainlink 自身のもので、「ローンチパートナー」が稼働中の統合を意味するとは限りません。

今週やること

  • Lightning ライブラリのバージョンを固定して監査し、再接続やチャネル再確立の境界ケースをテストする。
  • 有料 API では、L402（ビットコイン）と x402（ステーブルコイン）の両方への対応を検討する。
  • CCIP 2.0 を統合するときは、誰が検証者を運用するか、拒否やオフライン時にどうなるかを決めておく。
  • Bitcoin Optech の週刊セキュリティリリース欄を追う。

Lightning Labs · アルファ版 · 10月25日

Wavelength で AI エージェントがビットコインで支払い

Lightning Labs は Wavelength を一般公開しました。人が1件ずつ承認しなくても、ソフトウェアのエージェントが Lightning でビットコインを送受信できるようにするものです（TokenPost）。ウェブの「支払いが必要」エラーと Lightning の請求書を組み合わせる L402 を使い、Coinbase の x402 に似ていますが、ステーブルコインではなくビットコインで決済します。開発者はノードを動かす必要がありません。ウォレットはセルフカストディで、上限は当初30万 sat（約240ドル）、手数料は0.25%です。まだアルファ版です。

未確認報道は今のところ1件のみで、利用状況の数字はありません。

Lightning · やさしい解説

Lightning ウォレットを更新しよう

ビットコインの高速決済ネットワーク Lightning のウォレットの多くを支えるソフトで、今月いくつもの重大なバグが修正され、攻撃者はすでに未修正のノードを探っていました。損失は確認されていませんが、ウォレットアプリを更新すれば済む話です。

利用者として

  • Lightning ウォレット、特に Phoenix など LDK ベースのものは今すぐ更新する。
  • 自分で Lightning ノードを運用しているなら、CLN v26.06.9、LDK 0.2.7、Eclair 0.14.5 以降にアップグレードする。
  • AI エージェントには上限付きの小さな専用ウォレットを与え、メインの資金には触れさせない。
  • チェーン間を移動するトークン化資産には発行体のチェックが入ることがあり、送金が意図的に遅れたり止められたりする場合があります。

今後の予定：LND の正式リリース、Glamsterdam の Hoodi の新しい日程、CCIP 2.0 の最初の稼働中の統合。
